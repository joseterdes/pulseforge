# Local MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PulseForge you can QA on localhost. Sign in, upload a song (or pick a vibe preset), see its BPM, key and energy, adjust the vibe in plain words, generate tracks, play them in the browser and download WAV or MP3. On the laptop a built-in test generator makes the music; on the home PC the same app uses Stable Audio Open / ACE-Step on the RTX 3060.

**Architecture:** Builds on the M1a backend ([2026-10-28-m1a-backend-foundation.md](2026-10-28-m1a-backend-foundation.md), which must be done first). It follows BLUEPRINT §4 at local scale:
- The API owns the database and a Postgres job queue.
- A separate **worker** process claims jobs over the `/internal` HTTP API with a worker token, so it never holds DB credentials. It runs analysis and generation and reports results; the orchestrator in the API advances state.
- Files live in a **local storage** directory behind HMAC-signed URLs served by the API, standing in for R2 presigned URLs, so the browser upload flow is the same as production.
- Uploaded audio only ever produces an analysis and a style profile. **Generators receive a `GenerationSpec` and never the reference audio** (the firewall, BLUEPRINT §4.2).

**Tech Stack:**
- Backend: as M1a + numpy, soundfile, librosa, pyloudnorm, imageio-ffmpeg (bundled ffmpeg binary; no system install), httpx (worker client).
- Web: Next.js (App Router, TypeScript strict, Tailwind) + openapi-typescript + openapi-fetch, managed with pnpm; Playwright for the end-to-end smoke test.

**Spec:** [docs/BLUEPRINT.md](../../BLUEPRINT.md): §1.3 (Simple/Pro modes, vibe presets), §4 (architecture, orchestrator, provider interface, request flows), §5 (analysis), §6 (style profiles), §7 (prompt builder), §8.1 (post-processing), §9 (schema), §10 (API), §11 (layout), §17.3–17.4 (upload rights, retention, firewall).

## Global Constraints

- Everything in the M1a plan's Global Constraints still applies (Python 3.12, uv, problem+json, `/v1`, ruff 0.17.3, branch + PR, noreply commits).
- Work on branch `feat/local-mvp`, created from `main` after M1a is merged.
- Patterns established in M1a that every new route and table must reuse:
  - **Transactions:** use `DbSession` from `api/deps.py`. It is the single transaction owner and commits before the response is sent. Routes never call `session.commit()`; use `session.flush()` when they need generated values.
  - **Free text:** every free-text request field uses `plain_text(min_length, max_length)` from `api/types.py`, which strips whitespace and rejects control characters.
  - **Auth in OpenAPI:** new authenticated routers declare the bearer security scheme the way `/v1/me` does.
  - **Timestamps:** new `updated_at` columns use `onupdate=func.now()` in the ORM model.
  - **HTTP client:** use **`httpx2`**, not `httpx` (Starlette 1.10's TestClient requires it). The worker's HTTP client is `httpx2.Client`.
- New settings (env vars), with exact names and defaults:
  - `APP_ENV` = `production` | `local` (default **`production`**)
  - `AUTH_MODE` = `supabase` | `dev` (default `supabase`)
  - `SUPABASE_URL`: required only when `AUTH_MODE=supabase`
  - `DATA_DIR` (default `.data`)
  - `STORAGE_SIGNING_SECRET` (required, ≥ 32 chars)
  - `WORKER_TOKEN` (required, ≥ 32 chars)
  - `PUBLIC_API_URL` (default `http://localhost:8000`)
  - `CORS_ORIGINS` (comma-separated, default empty)
  - `DEFAULT_PROVIDER` (default `fake`)
  - `UPLOAD_MAX_BYTES` (default `104857600`, 100 MB)
  - `UPLOAD_MAX_SECONDS` (default `1200`, 20 min)
  - `UPLOAD_RETENTION_HOURS` (default `24`)
- **`create_app` must raise `RuntimeError` when `AUTH_MODE=dev` and `APP_ENV` is not `local`.** Dev login must be impossible to enable in production by one wrong variable.
- Accepted upload extensions: `.mp3 .wav .flac .m4a .aac .ogg .aif .aiff`. `rights_attested` must be `true`. Uploads larger than `UPLOAD_MAX_BYTES` are refused at creation and at PUT (413). Decoded audio longer than `UPLOAD_MAX_SECONDS` → upload status `rejected`.
- Raw uploaded audio is deleted `UPLOAD_RETENTION_HOURS` after analysis; the analysis stays (BLUEPRINT §17.3).
- Every user-owned resource is scoped by the token's `sub`. Another user's id gives **404**, never 403, so ids can't be probed.
- Signed URLs expire after **15 minutes**, and the signature covers method, key, expiry and max bytes.
- Generators never receive uploaded audio, file paths of uploads, song titles or artist names. They receive only a `GenerationSpec`.
- Allowed provider names: `fake`, `stable_audio_open`, `ace_step`. `musicgen` is **never** selectable in the app (non-commercial weights).
- Web app text in Simple mode uses plain words, not "BPM" or "Camelot" (BLUEPRINT §1.3); Pro mode shows the technical values.
- Out of scope here, deferred and listed in STATUS.md: Supabase login UI, link input (Stage 0), quotas/usage ledger, similarity gate (§8.3), automatic regeneration loop, CLAP genre tagging, groove/drum extraction, stems, deployment.

## Review Focus

1. **A file that isn't audio** (a renamed .txt or .zip with an .mp3 extension, or a truncated file) must end as `rejected` with a readable reason, not leave the upload stuck in `analyzing` or crash the worker. Covered in Task 4 by `test_analyze_job_rejects_non_audio` and `test_analyze_job_rejects_truncated_file`.
2. **A worker that dies mid-job** (laptop sleeps, PC crashes) must have its job re-queued once the 60 s lease expires and be retried up to `max_attempts=3`, then marked `failed` with the generation or upload showing an error, never stuck "processing" forever. Covered in Task 3 by `test_expired_lease_is_requeued` and `test_job_dead_after_max_attempts_marks_target_failed`.
3. **Tampered or expired signed URLs** (changed key, expiry or max) must give 403, and a PUT larger than its signed max must give 413 with no partial file left behind. Covered in Task 2 by `test_signed_url_tampering_rejected` and `test_put_over_max_bytes_rejected_and_cleaned`.
4. **Accessing another user's upload, profile, generation or output by id** must give 404. Covered in Task 2 (`test_other_users_upload_is_404`), Task 5 (`test_other_users_profile_is_404`) and Task 6 (`test_other_users_generation_and_output_are_404`).
5. **Very long uploads such as a 2-hour DJ mix under the size cap** must be refused by duration (`rejected`, "longer than 20 minutes") without decoding the whole file into memory first. Covered in Task 4 by `test_analyze_job_rejects_too_long_without_full_decode`, which uses a probe that reads only the duration.

## Shared contracts (defined once, used across tasks)

`backend/src/pulseforge/domain.py` (Pydantic models, created in Task 3 and extended later):

- `JobType = Literal["analyze", "generate", "purge_upload"]`, `Queue = Literal["cpu", "gpu"]`
- `ClaimedJob {id: UUID, type: JobType, payload: dict, attempts: int}`
- `AnalysisResult {analyzer_version: str, duration_s: float, bpm: float, key: str, camelot: str, key_confidence: float, energy_mean: float, energy_curve: list[float], loudness_lufs: float}`. `key` uses sharps, e.g. `"A minor"`; `energy_curve` has 16 values in 0–1.
- `GenerationSpec {genre: str, bpm: int, key: str, moods: list[str], instruments: list[str], duration_s: int, seed: int}`. This is the **only** input a provider gets, and it has the same field names as `phase0/specs.json`.
- `OutputMetrics {bpm_detected: float, bpm_error: float, key_detected: str, key_match: Literal["exact","relative","no"], loudness_lufs: float, clipping_pct: float}`

Database tables (migration `0002`, per BLUEPRINT §9, trimmed to what this plan uses):
- `uploads`: id, user_id, original_filename, content_type, size_bytes, storage_key, status `pending|uploaded|analyzing|analyzed|rejected|failed|purged`, reject_reason, rights_attested, duration_s, purge_after, purged_at, created_at
- `audio_analyses`: id, upload_id UNIQUE, analyzer_version, result jsonb (`AnalysisResult`), created_at
- `style_profiles`: id, user_id NULL for presets, kind `preset|user`, slug NULL, name, derived jsonb, overrides jsonb default `{}`, created_at, updated_at
- `style_profile_sources`: style_profile_id, upload_id
- `generations`: id, user_id, style_profile_id, controls jsonb, spec jsonb, provider, status `queued|generating|ready|failed`, error, created_at, completed_at
- `generation_outputs`: id, generation_id, variation int, seed, duration_s, storage_key_wav, storage_key_mp3, metrics jsonb, created_at
- `jobs`: id, type, queue, payload jsonb, result jsonb, status `queued|running|succeeded|failed|dead`, priority, attempts, max_attempts default 3, run_after, locked_by, locked_at, heartbeat_at, error, created_at, finished_at; partial index on `(queue, priority desc, run_after) WHERE status='queued'`

### Task 3: Job queue, internal worker API, worker runtime

**Files:** extend `queue/jobs.py`; create `domain.py`, `api/routers/internal.py`, `orchestrator/handlers.py`, `worker/client.py`, `worker/runtime.py`, `worker/main.py`; `tests/test_jobs.py`, `tests/test_internal_api.py`, `tests/test_worker_runtime.py`. Add the `[project.scripts]` entries `pulseforge-api = "pulseforge.api.main:run"` and `pulseforge-worker = "pulseforge.worker.main:main"`.

**Interfaces:**
- Produces:
  - `claim(session, *, worker_id: str, queues: list[Queue], providers: list[str]) -> ClaimedJob | None`. It first re-queues `running` jobs whose `heartbeat_at < now() - 60 s`, then picks the highest priority and oldest job with `run_after <= now()` using `FOR UPDATE SKIP LOCKED`. A `generate` job is claimable only if `payload["provider"] in providers`. Claiming increments `attempts`.
  - `heartbeat(session, job_id, worker_id) -> None` (409 if the job is no longer locked by this worker)
  - `complete(session, job_id, worker_id, result: dict) -> None` → calls `orchestrator.on_complete(session, job, result)`
  - `fail(session, job_id, worker_id, error: str, retryable: bool) -> None`: if retryable and `attempts < max_attempts`, back to `queued` with `run_after = now() + 30 s * attempts`; else `dead` → `orchestrator.on_dead(session, job)`
  - Orchestrator registry: `HANDLERS: dict[JobType, JobHooks]` where `JobHooks` is a dataclass with `on_claim(session, job)`, `on_complete(session, job, result)` and `on_dead(session, job)`. `claim()` calls `on_claim` in the same transaction. Task 3 registers no-op hooks; Tasks 4 and 6 fill them in.
  - Internal routes, protected by `Authorization: Bearer {WORKER_TOKEN}` (constant-time compare; 401 otherwise): `POST /internal/jobs/claim {worker_id, queues, providers}` → 200 `ClaimedJob` or 204; `POST /internal/jobs/{id}/heartbeat|complete|fail`; `POST /internal/storage/presign {method, key, max_bytes?}` → `{url}` (only `uploads/` and `outputs/` keys).
  - `WorkerClient(api_url, token)`, with methods that mirror the routes.
  - `Worker(client, worker_id, queues, providers, handlers: dict[JobType, Callable[[ClaimedJob, WorkerClient], dict]])`; `run_once() -> bool` (returns whether a job ran); `run_forever(poll_s=2.0)`. A heartbeat thread runs every 15 s during a job. A handler raising `PermanentJobError` → `fail(retryable=False)`; any other exception → `fail(retryable=True)`.
  - CLI: `pulseforge-worker --api-url URL --queues cpu gpu --providers fake [--once]`, with `WORKER_TOKEN` from env.

### Task 4: Audio analysis and the analyze/purge jobs

**Files:** create `analysis/decode.py`, `tempo.py`, `key.py`, `energy.py`, `analyze.py`; worker handlers in `worker/handlers.py`; fill in the `analyze`/`purge_upload` orchestrator handlers; tests `tests/analysis/test_*.py` (synthetic audio generated in the tests), `tests/test_analyze_flow.py`

**Interfaces:**
- Produces:
  - `probe_duration(path: Path) -> float`: reads only the container header (`soundfile.info` for wav/flac/ogg/aiff; for mp3/m4a/aac, parse ffmpeg's `Duration:` line from `ffmpeg -i` stderr, with the binary from `imageio_ffmpeg.get_ffmpeg_exe()`). Raises `UnreadableAudio`.
  - `decode(path: Path, sr: int = 22050, *, offset_s: float = 0, duration_s: float | None = None) -> np.ndarray` (mono float32 via ffmpeg pipe `-f f32le`)
  - `estimate_tempo(y, sr) -> float`: same algorithm as `phase0/evaluate.py::estimate_tempo`, ported with its docstring
  - `estimate_key(y, sr) -> tuple[str, float]` (key, confidence = correlation) and `camelot(key: str) -> str` (A minor → `8A`, C major → `8B`, the full wheel)
  - `energy_curve(y, sr, points=16) -> list[float]` (RMS per segment, normalized to 0–1 by the loudest segment), `loudness_lufs(y, sr) -> float`
  - `analyze_file(path: Path, *, max_seconds: float) -> AnalysisResult`. Files longer than 6 min are analyzed from 8 evenly spaced 30 s windows: the median tempo, the key with the highest summed correlation, and the energy curve across windows. `ANALYZER_VERSION = "1"`.
  - The worker `analyze` handler downloads via a presigned GET into a temp dir. A too-long file raises `PermanentJobError("longer than 20 minutes")`; an undecodable one raises `PermanentJobError("not a supported audio file")`. On success it returns `AnalysisResult.model_dump()`.
  - Orchestrator: analyze `on_complete` → inserts `audio_analyses`, upload `analyzed`, `purge_after = now + UPLOAD_RETENTION_HOURS`, and enqueues `purge_upload` with `run_after = purge_after`. `on_dead` → upload `rejected` with `reject_reason` = the job error if permanent, else `failed`. Upload status becomes `analyzing` when the job is claimed.
  - Worker `purge_upload` handler → presigned DELETE; orchestrator → `storage_key = NULL`, `status = purged`, `purged_at`.

### Task 6: Providers, generation, post-processing, playback and download

**Files:** create `providers/base.py`, `providers/fake.py`, `providers/phase0.py`, `providers/registry.py`, `postprocess.py`, `api/routers/generations.py`, `api/routers/outputs.py`; worker `generate` handler; orchestrator generate handlers; tests `tests/test_providers.py`, `tests/test_postprocess.py`, `tests/test_generations.py`

**Interfaces:**
- `class Provider(Protocol): name: str; max_seconds: int; commercial_ok: bool; def generate(self, spec: GenerationSpec, out_wav: Path) -> None`
- `FakeProvider` (`max_seconds=600`): a deterministic numpy synth at `spec.bpm`, 44.1 kHz stereo. Kick on every beat, closed hat on off-beats, a bass note on the key's root each bar, and a sustained triad of the key in the pad. The seed varies hat velocity and the bass rhythm. Audibly "a loop in the right tempo and key", for QA.
- `Phase0Provider(name, env_python: Path, script: Path, max_seconds)`: writes a one-job `jobs.json` (`{job_id, spec: {id: "app", **spec fields}, duration_s, seed}`), runs the script with `subprocess.run(..., timeout=900)`, reads `results.jsonl`, and moves the WAV to `out_wav`. On failure it raises `RuntimeError` with the provider's error text.
- `available_providers(repo_root: Path) -> dict[str, Provider]`: always `fake`; `stable_audio_open` (max 47) if `phase0/envs/hf/bin/python` exists; `ace_step` (max 240) if `phase0/envs/ace_step/bin/python` exists. `musicgen` is never registered.
- `postprocess(raw_wav: Path, out_dir: Path) -> tuple[Path, Path]`: `master.wav` (PCM 16-bit 44.1 kHz, true-peak limited to −1 dBTP with ffmpeg `alimiter`) and `preview.mp3` (192 kbps, `loudnorm=I=-14:TP=-1`).
- `measure(wav: Path, spec: GenerationSpec) -> OutputMetrics` (reuses the analysis functions).
- Routes:
  - `POST /v1/generations {style_profile_id, controls: Controls}` → 202 `GenerationOut`. It picks `provider = settings.DEFAULT_PROVIDER` and clamps `duration_s` to that provider's max (recorded in the response as `duration_s`). It enqueues **one `generate` job per variation**, queue `gpu`, payload `{generation_id, variation, provider, spec}` with `spec.seed = random 31-bit`.
  - `GET /v1/generations` (newest first, with outputs); `GET /v1/generations/{id}` → `GenerationOut {id, status, provider, controls, spec, error, created_at, completed_at, outputs: [{id, variation, duration_s, metrics, stream_url, download_wav_url, download_mp3_url}]}`. URLs are freshly signed on each GET (15 min).
  - `GET /v1/outputs/{id}/stream` → 302 to signed mp3; `GET /v1/outputs/{id}/download?format=wav|mp3` → 302 to a signed URL with `Content-Disposition: attachment; filename="pulseforge-{genre-slug}-{bpm}bpm-{variation}.{ext}"` (the `/files` GET accepts an optional signed `dl` filename parameter).
- Worker `generate` handler: the provider writes `raw.wav`, then postprocess, measure, and presigned PUT of both files. It returns `{variation, seed, duration_s, metrics, storage_key_wav, storage_key_mp3}`. Generation status becomes `generating` when the first job is claimed; `ready` when all variations are complete; `failed` (with the first error) if any job is dead and none are ready.
